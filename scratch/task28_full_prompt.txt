## PART B — INVENTORY REPLENISHMENT / HOW MUCH STOCK TO BUY

This is particularly important for the academic demonstration.

The user must be able to select a SKU, provide the currently available stock, and receive a recommendation explaining how much additional stock should be purchased.

First inspect whether a genuine inventory recommendation endpoint already exists.

If it does, use and document it.

If it does not, implement a properly integrated endpoint using the existing forecasting service and project architecture. Do not create a disconnected mock endpoint.

Suggested endpoint:

`POST /api/v1/inventory/recommend`

Suggested request:

```json
{
  "stock_code": "85123A",
  "current_stock": 100,
  "lead_time_days": 7,
  "review_period_days": 7,
  "safety_stock_days": 3
}
```

Adapt field names to the actual project conventions.

The recommendation must:

1. Validate that the SKU exists.
2. Validate that enough historical data is available.
3. Obtain the demand forecast from the existing trained model.
4. Calculate expected demand over the lead time and review period.
5. Calculate safety stock using a clearly documented method.
6. Compare projected demand and safety stock against current available stock.
7. Return a non-negative recommended purchase quantity.
8. Explain the calculation in the response.
9. Handle invalid quantities and insufficient history properly.

A transparent baseline formula is:

`Target Stock = Forecast Demand During (Lead Time + Review Period) + Safety Stock`

`Recommended Purchase Quantity = max(0, Target Stock - Current Stock)`

Use daily forecasts or a documented, defensible method to estimate the requested coverage period. Do not simply multiply a D7 or D30 forecast by an arbitrary factor if a more appropriate method is available.

If the existing model only provides fixed horizons, document how interpolation or scaling is performed and validate the approach.

Do not confuse predicted demand with guaranteed sales.

### Required inventory recommendation response

Return fields equivalent to:

```json
{
  "stock_code": "85123A",
  "current_stock": 100,
  "forecast_demand": 250,
  "lead_time_days": 7,
  "review_period_days": 7,
  "safety_stock": 30,
  "target_stock": 280,
  "recommended_purchase_quantity": 180,
  "recommendation": "Purchase 180 additional units",
  "calculation_explanation": "Target stock is forecast demand plus safety stock. Current stock is subtracted to calculate the purchase quantity."
}
```

These numbers are illustrative only. Actual API output must come from the actual model and calculation.
